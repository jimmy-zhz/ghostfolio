## 2. 资金分组

### 2.1 背景

账户（DI、FHSA、TFSA）回答“钱放在哪”，这个区分要保留。另外还要两个维度：

| 维度 | 回答的问题   | 每笔交易               | 要不要全覆盖       | 关心的数字     |
| ---- | ------------ | ---------------------- | ------------------ | -------------- |
| 账户 | 钱放在哪     | 必有一个               | 是                 | 余额、市值     |
| 来源 | 钱是谁的     | **正好一个**           | 是，“其余”来源兜底 | 本金、收益     |
| 用途 | 钱打算干什么 | **可以没有，最多一个** | 否                 | 目标金额、进度 |

三个维度互不冲突。例如 TFSA 里的一笔 XUS 买入，可以同时是“来源：我的储蓄”和“用途：买车”。

现在的来源：

| 来源     | 约定本金 | 说明                                 |
| -------- | -------- | ------------------------------------ |
| 老婆保管 | 2,000    | 替老婆保管，本金和收益都是她的       |
| 老婆赠予 | 10,000   | 将来可能有单独的用途                 |
| 母亲赠予 | 15,000   | 将来可能有单独的用途                 |
| 我的储蓄 | 其余     | 名称可改；金额由合计减去其他来源算出 |

用途举例：买车，目标 30,000，由 XUS、XIC 等几只股票组成，不限账户，也不限来源。

### 2.2 方案：标签做底，加一层分组定义

- **区分靠标签。** 每笔交易打来源标签（如 `来源·母亲赠予`），需要时再打用途标签（如 `用途·买车`）。Ghostfolio 按标签筛选时只用带该标签的交易计算持仓和收益（`portfolio.service.ts` 的 `filtersByTag`），所以每个分组能独立算清。用户可以在交易弹窗的 Tags 里直接输入新名字创建标签（`createOwnTag` 权限，普通用户有）。
- **结构靠新表。** 标签本身不知道“这是一份钱、本金多少、目标多少”，所以加一张资金分组表，把标签和这些信息关联起来。来源和用途共用这张表，用 `kind` 区分。
- 不新建一套账本，不改交易和账户的结构。

### 2.3 打标签的规则（写进 `docs/guide/investment-features.md`）

来源：

1. 每笔交易（买入、卖出、分红）正好打一个来源标签，打两个会被两边各算一次。
2. “我的储蓄”也要打标签：系统不能筛选“没有标签的交易”。
3. 一笔买入用了两份钱就拆成两笔记，数量和手续费按比例拆。
4. 卖出要标明卖的是哪份钱的股票。

用途：

5. 用途标签可以不打，最多打一个。
6. 一只股票整体属于某个用途时，它的所有买入、卖出、分红都打这个用途标签，不用拆。只有一笔买入里一部分属于某个用途时才拆。
7. 以后再买这只股票，记得也打上用途标签（第 2.5 节有检查项提醒）。

通用：

8. 分组标签只打在交易上，不打在账户上：账户带标签会把这个账户的所有交易都算进去。

### 2.4 数据模型

```prisma
enum FundGroupKind {
  SOURCE
  PURPOSE
}

model FundGroup {
  id           String         @id @default(uuid())
  kind         FundGroupKind
  name         String
  note         String?        // 备注
  sortOrder    Int            @default(0)
  // 来源
  principal    Float?         // 约定本金，基础货币
  isRemainder  Boolean        @default(false) // “其余”来源：本金由合计减去其他来源算出；每个计划最多一个
  // 用途
  targetAmount Float?         // 目标金额，基础货币
  targetDate   DateTime?      // 目标日期，可选
  tagId        String
  tag          Tag            @relation(fields: [tagId], references: [id])
  planId       String
  plan         InvestmentPlan @relation(fields: [planId], references: [id], onDelete: Cascade)
  createdAt    DateTime       @default(now())
  updatedAt    DateTime       @updatedAt

  @@unique([planId, tagId])
  @@index([planId])
}
```

- 挂在投资计划下（和价格提醒、定投一样）。
- 校验：`isRemainder` 只用于来源，每个计划最多一个；`principal` 只用于来源；`targetAmount`、`targetDate` 只用于用途；同一个标签不能同时是来源和用途。
- **用途的“来源构成”不做**（比如“买车篮子里 70% 是我的储蓄、30% 是老婆赠予”）：现有标签筛选多个标签时是“或”，算构成要“且”，需要新写计算，放到以后。

### 2.5 计算和检查

每个分组按它的标签筛选（`range=max`），复用现有计算，不写新的收益算法：

| 字段           | 来源                                                                      | 用于 |
| -------------- | ------------------------------------------------------------------------- | ---- |
| 已投入         | 筛选后的 `totalInvestment`                                                | 两者 |
| 市值           | 筛选后的当前市值                                                          | 两者 |
| 收益额、收益率 | 筛选后的 `netPerformanceWithCurrencyEffect`（含分红），收益率与持仓页一致 | 两者 |
| 账户分布       | 筛选后的账户维度汇总（DI / FHSA / TFSA 各多少）                           | 两者 |
| 持仓           | 筛选后的持仓列表（用途卡片展开时显示篮子里有哪些股票）                    | 两者 |
| 差额           | 约定本金 − 已投入。不为 0 时提示：可能有钱没投出去，也可能漏打了标签      | 来源 |
| 进度           | 市值 ÷ 目标金额；有目标日期时显示剩余月数                                 | 用途 |

“其余”来源的约定本金 = 全部已投入 − 其他来源的约定本金之和。

检查项：

| 检查                                   | 对象 | 级别                                         |
| -------------------------------------- | ---- | -------------------------------------------- |
| 各来源市值之和 ≠ 全部账户市值          | 来源 | 警告：有交易没归到任何来源                   |
| 没有来源标签的交易（买入、卖出、分红） | 来源 | 警告，可点开列表                             |
| 有多个来源标签的交易                   | 来源 | 警告，可点开列表                             |
| 有多个用途标签的交易                   | 用途 | 警告，可点开列表                             |
| 某只股票只有部分交易带某个用途标签     | 用途 | 提示（可能是有意拆分，也可能是新买入忘了打） |

“分组标签”指被某个 FundGroup 关联的标签，Draft、Exclude from Analysis 等系统标签不算。

## 3. 价格提醒规则

### 3.1 背景

现在的价格提醒只有“价格高于或低于某个固定值”。实际要盯的多是相对变化：从高点回撤多少、相对成本涨跌多少、单日大涨大跌。原则是**每条提醒都对应一个事先定好的动作**，否则提醒多了只是噪音，还会诱导临场操作。

现状（`price-alert.service.ts`、`cron.service.ts`）：

- 每 10 分钟（`*/10 * * * *`）取一次实时报价，和 `targetValue` 比较。
- 触发后发邮件或 webhook，然后 `isActive=false`，要手动 `rearm` 才会再触发。

### 3.2 规则（分两期，本迭代只做第一期）

| 期   | 规则 `ruleType` | 比较的指标                      | 例子                             | 对应的动作                         |
| ---- | --------------- | ------------------------------- | -------------------------------- | ---------------------------------- |
| 现有 | `PRICE`         | 当前价                          | XUS ≤ 40                         | 按预设执行                         |
| 一   | `PCT_FROM_HIGH` | 相对 N 日最高收盘价的涨跌（%）  | XUS 比 52 周高点低 15%           | 启动或检查加仓的分档挂单           |
| 一   | `PCT_FROM_COST` | 相对持仓平均成本的涨跌（%）     | CHPS 回到成本（0%）；投机仓 −50% | 按投资记录里写好的动作执行         |
| 一   | `DAILY_CHANGE`  | 相对上一交易日收盘的涨跌（%）   | 指数单日 ≤ −3%，单股 ≥ 8%        | 只看消息、不操作，提醒自己按计划来 |
| 二   | `PCT_FROM_LOW`  | 相对 N 日最低收盘价的涨跌（%）  | BTC 从近期低点反弹 15%           | 投机仓高抛低吸                     |
| 二   | `TRAILING`      | 相对建立提醒后最高价的回落（%） | 涨过 8.2 万后回落 8%             | 移动止盈                           |
| 二   | `MA_CROSS`      | 当前价相对 N 日均线             | XUS 跌破 200 日均线              | 判断大趋势，决定加仓节奏           |

`PCT_FROM_COST` 的成本按全部账户合计；按账户或按资金分组算成本放到以后。

暂不做：配置偏离提醒（已有再平衡）、VIX 和汇率、事件日历（财报、除息，放日历更合适）。

### 3.3 数据模型

在 `PriceAlert` 上加字段，不新建表：

```prisma
enum PriceAlertRuleType {
  PRICE
  PCT_FROM_HIGH
  PCT_FROM_COST
  DAILY_CHANGE
}

model PriceAlert {
  // ...现有字段
  ruleType     PriceAlertRuleType @default(PRICE)
  lookbackDays Int?    // PCT_FROM_HIGH 的 N，默认 252（约 52 周交易日）
  actionNote   String? // 触发时该做什么，原文附在通知里
}
```

- 统一的判断方式：按 `ruleType` 算出一个指标，再用现有的 `condition` 和 `targetValue` 比较。`PRICE` 时指标是价格；其他规则的指标是百分比，`targetValue` 也填百分比。例如“比 52 周高点低 15%”是 `PCT_FROM_HIGH`，`condition=LESS_THAN_OR_EQUAL`，`targetValue=-15`。
- 现有提醒迁移后都是 `PRICE`，行为不变。

### 3.4 计算细节和风险

| 规则            | 需要的数据          | 来源                                                              | 风险                                                                                                                                                                                          |
| --------------- | ------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PCT_FROM_HIGH` | 近 N 个交易日收盘价 | `MarketData` 表（定投信号也从这里取）                             | 只有持仓、关注列表、基准里的标的才有历史行情。别的标的需要在建提醒时触发一次历史数据收集，或者用 `dataProviderService.getHistorical` 现取                                                     |
| `PCT_FROM_COST` | 用户的平均成本      | 持仓的 `averagePrice`                                             | `PortfolioService` 依赖请求上下文（`@Inject(REQUEST)`），定时任务里不能直接用。需要抽出一个不依赖请求的成本计算，或者按用户构造上下文。**这是本迭代技术风险最大的一项，开发前先做一个小验证** |
| `DAILY_CHANGE`  | 上一交易日收盘价    | `MarketData` 里最近一条早于今天的收盘价；报价里如有前收盘价优先用 | 节假日、停牌时上一交易日要按实际有数据的那天算                                                                                                                                                |

- **重复触发：** `PRICE`、`PCT_FROM_HIGH`、`PCT_FROM_COST` 仍是一次性的，触发后关闭，要 `rearm`。`DAILY_CHANGE` 每个交易日最多触发一次，第二天自动重新生效，否则这条规则用一次就废了。
- **数据不足：** 历史行情少于所需天数时不触发，日志里写明原因，不按不完整的数据算。

### 3.5 通知内容

在现有邮件和 webhook 的基础上，写明规则、当前值、参照值和要做的动作。例如：

> XUS.TO 比 52 周最高收盘（47.20，2026-09-18）低 15.3%，当前 39.98。
> 动作：按加持计划第 5–6 档执行。

Discord embed 加“规则”“参照”“动作”三个字段。

### 3.6 界面

- 新建或编辑提醒时先选规则类型，表单随类型变化：`PRICE` 填价格；`PCT_FROM_HIGH` 填天数（默认 52 周）和百分比；`PCT_FROM_COST` 和 `DAILY_CHANGE` 填百分比。
- 每种类型都有“动作”输入框（`actionNote`）。
- 列表里每条提醒用一句话描述规则，比如“比 52 周高点低 ≥ 15%”，不再只显示条件和数值。
- 手机上同样两行显示。

### 3.7 MCP

- `create_price_alert`、`update_price_alert` 增加 `ruleType`、`lookbackDays`、`actionNote` 参数。描述里写清 `targetValue` 在非 `PRICE` 规则下是百分比，并给出“比 52 周高点低 15%”的完整例子。
- `get_investment_plan` 返回的提醒带上新字段。
- 不新增工具，白名单不变。

## 4. 首页导航

常用的 Overview、Holdings、投资计划、Activities 分在首页和 Portfolio 两处，手机上切换要先换区再选标签。调整为：

| 位置      | 调整前                                                   | 调整后                                               |
| --------- | -------------------------------------------------------- | ---------------------------------------------------- |
| 首页      | Overview、Holdings、Summary、Watchlist、Markets          | Overview、Holdings、投资计划、Activities、Watchlist  |
| Portfolio | 投资计划、Analysis、Activities、Allocations、FIRE、X-Ray | Analysis、Allocations、FIRE、X-Ray、Summary、Markets |

## 6. 单元测试要覆盖的

- 资金分组：
  - 计算：已投入、市值、收益、分布、差额、进度；“其余”本金由合计减去其他来源。
  - 校验：“其余”最多一个；字段只用于对应的类型；同一标签不能既是来源又是用途。
  - 检查项：没有来源标签、多个来源标签、多个用途标签、部分交易带用途标签。
  - 按 id 写的接口只认自己计划里的记录。
- 批量打标签：只改自己的交易；加和去都是幂等的。
- 价格提醒：
  - 每种规则的指标计算。
  - 数据不足时不触发。
  - `DAILY_CHANGE` 一天最多一次、次日自动生效。
  - 现有 `PRICE` 提醒行为不变。
  - 通知内容带上参照值和动作。
- 导航：旧地址（含交易编辑、复制）重定向到新地址。
- MCP：新参数的校验；`get_fund_groups` 的返回结构；工具清单和注解测试随之更新。

## 7. 验收

1. 补完标签后，三个来源的已投入分别是 2,000、10,000、15,000（或有清楚的差额提示），合计和账户页一致。
2. 建“买车”用途，把 XUS、XIC 的交易打上用途标签，卡片显示市值、进度、篮子里的持仓。
3. 点某个分组能看到它的持仓和账户分布。
4. 在活动表多选交易，一次加上标签。
5. 建一条“XUS.TO 比 52 周高点低 X%”的提醒，X 取一个当前已满足的值，10 分钟内收到带参照值和动作的通知。
6. 建一条单日涨跌提醒，当天最多收到一次，第二天自动生效。
7. 原有的固定价格提醒照常工作。
8. 通过 MCP 能读资金分组、能建新规则的提醒。
9. 手机首页底部是 Overview、Holdings、投资计划、Activities、Watchlist；旧书签能打开。
10. 手机上资金分组卡片、提醒列表都不能左右滑，显示成两行。
11. 电脑上其他页面和以前一样。
