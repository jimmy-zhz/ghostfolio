# ADR 0005 — MCP 可以改交易的标签（只改标签）

- 状态：已采纳（2026-11-27）
- 扩展：[ADR 0002](0002-mcp-single-write-exception.md)（交易通过 MCP 只能新增，不能修改）
- 相关：[ADR 0004](0004-mcp-investment-plan-writes.md)、[2026-12 迭代需求](../requirements/iteration-2026-12.md)

## 背景

2026-12 迭代加了资金分组：来源（钱是谁的）和用途（钱打算干什么），都靠交易上的标签区分。现有 102 笔交易要补标签，
用户希望 agent 协助：列出交易、由用户说明归属、确认后批量打上。

## 决策

开放两个写工具：

| 工具             | 接口                       | 作用                                                       |
| ---------------- | -------------------------- | ---------------------------------------------------------- |
| `create_tag`     | `POST /activity-tags/tags` | 建用户自己的标签；同名已存在就返回那个，重复调用没有副作用 |
| `tag_activities` | `PUT /activity-tags`       | 给最多 100 笔交易加或去一个标签                            |

同时开放资金分组的增删改（`upsert_fund_group`、`delete_fund_group`，规则同 ADR 0004）和只读的 `get_fund_groups`。

边界：

- **只改标签。** 接口只写交易和标签的关联，金额、数量、日期、账户都不碰。交易的其他修改仍只能在界面里做。
- **只能用自己的标签。** 系统标签会改变交易的处理方式：`Exclude from Analysis` 改变计算，`Draft` 改变交易状态，
  `Emergency Fund` 改变应急资金。接口拒绝没有 `userId` 或属于别人的标签。
- **整批校验。** 一次最多 100 笔；只要有一笔不是当前用户的交易，整批拒绝，什么都不写。
- **建标签不收 user id。** 上游的 `POST /tags` 要在请求体里带 `userId`，MCP 拿不到也不该填，所以单独加了只建自己标签的接口。
- **新接口放在本仓库自己的模块**（`apps/api/src/app/activity-tags/`），不改上游的活动控制器：`PUT /activities/tags`
  会先被已有的 `PUT /activities/:id` 匹配，而且改上游文件以后同步上游容易冲突。
- 描述里写死：写之前把完整清单给用户确认；补来源时由用户说明哪笔属于哪份钱，agent 不能猜；每笔交易正好一个来源标签、
  最多一个用途标签；改完调用 `get_fund_groups` 汇报检查项。

## 取舍

- 去掉标签也会改变资金分组的结果，但可以再加回来，所以 `tag_activities` 不标 `destructiveHint`；删除分组定义
  （`delete_fund_group`）标了。
- 确认和“不猜”只靠提示词。检查项（没有来源、多个来源）能在事后发现错误，用户可以在活动页的 Edit Tags 里改回来。
